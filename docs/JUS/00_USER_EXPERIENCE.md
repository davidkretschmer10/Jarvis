# USER EXPERIENCE

Version: 1.0

Status: Draft

Last Updated: 2026-07-06 22:03:07 +02:00

Purpose: Define the target user experience for Jarvis as a local Windows AI assistant.

---

## 1. UX Target

The target experience is simple: the user states a goal and Jarvis helps complete it. The user should not need to think about which program to open, where a setting is hidden, which keyboard shortcut is needed, or how many steps a workflow requires.

Jarvis must feel like an intelligent layer over Windows. It should combine chat, voice, screen understanding, memory, and automation into one coherent assistant.

## 2. Core Experience

The user can interact with Jarvis through voice, text, visual context, and automation. These modes are not separate products. They are different ways of controlling the same assistant.

Voice is for fast, natural control. Text is for precision and long instructions. Vision is for understanding what is on screen. Automation is for carrying out actions. Memory is for continuity. GUI is for visibility, settings, control, and trust.

## 3. Everyday Flow

The ideal flow is:

1. The user gives Jarvis a goal.
2. Jarvis understands the goal and chooses the safest path.
3. Jarvis shows or says what it is doing.
4. Jarvis asks for confirmation when needed.
5. Jarvis completes the task or explains why it cannot.
6. Jarvis remembers useful context when appropriate.

The user must always feel that Jarvis is helping, not taking over.

## 4. Voice Experience

Voice must feel natural, fast, and interruptible. Jarvis should listen through wake word, push-to-talk, or hands-free mode. It should understand Czech and English, speak naturally, support interruption, and avoid unnecessary speech in gaming or meeting contexts.

The user should be able to control most common tasks without touching the mouse.

## 5. Desktop Experience

Jarvis must be able to open programs, control applications, work with files, type, click, read the screen, and perform workflows. These actions must be visible and safe. Destructive or sensitive actions require confirmation.

The user must never wonder whether Jarvis is idle, listening, thinking, acting, speaking, blocked, or waiting for confirmation.

## 6. Trust

Trust is part of UX. Jarvis must be transparent about what it knows, what it remembers, what it is about to do, and what failed. It must not hide errors behind personality. A clear failure is better than a confident wrong action.

## 7. UX Completion Standard

The UX is complete only when Jarvis can be used daily without confusion. The user must be able to start tasks, understand state, interrupt actions, review history, control memory, diagnose problems, and recover from failure.
